# translation-status

한국어가 원본이고 일본어가 번역본이므로, `ko`를 고친 뒤 `ja`를 안 고치면 번역이 **조용히** 낡는다.
frontmatter에 해시를 박는 대신 git이 이미 아는 사실(파일을 마지막으로 건드린 커밋 시각)을 비교한다.

## 절차

1. 리포 루트에서 실행:

   ```bash
   npm run i18n:status
   ```

   `--strict`를 붙이면 문제가 있을 때 exit 1이 된다 (CI에 걸 때 쓴다).

2. 출력은 세 갈래다:

   | 분류 | 의미 | 대응 |
   | --- | --- | --- |
   | 📝 번역 없음 | `ko`만 있고 `ja`가 없다 | `/translate-post <slug>` |
   | ⚠️ 뒤처짐 | `ko`를 고친 뒤 `ja`를 안 고쳤다 | 해당 부분만 재번역 → `/proofread-post` |
   | ❓ 원본 없음 | `ja`만 있다 | `ko` 원본을 만들거나 파일을 정리 |

3. **뒤처진 글을 처리할 때는 전체를 다시 번역하지 않는다.** `ko` 쪽에서 무엇이 바뀌었는지
   먼저 확인하고, 바뀐 부분만 `ja`에 반영한다:

   ```bash
   git log --oneline -- src/content/blog/ko/<slug>.md
   git diff <번역본을 마지막으로 고친 커밋>.. -- src/content/blog/ko/<slug>.md
   ```

   전체 재번역은 이미 다듬어 둔 일본어 표현을 날린다.

4. 결과를 요약해 보고한다. 문제가 없으면 그렇게 말하고 끝낸다 — 할 일을 만들어내지 않는다.

## 주의

- **아직 커밋되지 않은 파일은 뒤처짐 판정에서 빠진다.** 커밋 이력이 없으면 비교 기준이 없기
  때문이다. 방금 만든 글이 목록에 안 보이는 것은 정상이다.
- 커밋을 나눠서 `ko`와 `ja`를 따로 올리면 잠깐 뒤처짐으로 잡힌다. 같은 커밋에 담으면 깔끔하다.
